# pair-wise-yf-57 野外巡护离线调查应用

## 源提示词摘要
巡护员离线记录观察、轨迹点、样本编号、风险等级和现场情况，回到有网络环境后同步给站点负责人。负责人复核重复观察、位置异常、证据缺失和能力范围外事项；多人修改同一记录时保留版本并允许合并，应用需要适配手机屏幕、电量、弱网和后台恢复。

## 技术栈
Taro 3 + React + TypeScript + NutUI + Redux Toolkit + RTK Query + React Hook Form + Zod。

## 站点归并与同步规则（已实现）
1. **按现场时刻整理**：观察记录、轨迹点、同步队列一律按现场时刻（升序）排序，不按上传顺序；列表标题标注“按现场时刻 ↑”。
2. **晚到另存待协调，绝不覆盖**：两名巡护员改过同一条时，晚到的修改进入“待协调”列表（保留现场时刻、到站时刻、双方内容）；更新的来件成为主版本，更早的来件标 `stale` 留痕。协调方式：保留现版本 / 采用晚到版本 / 合并双方意见。
3. **地点或风险等级变更即级联失效**：观察记录的地点或风险一变，负责人复核结论立即失效（需重新复核）；关联样本中，已核验的退回“待核验”重做，**已送检样本只标“待确认”，不作废不退回**。纯备注修改不触发级联。“采用晚到版本”若改变风险/地点同样触发级联；“合并意见”保留现风险，不触发。
4. **失败重试只补未合完的项**：同步逐项进行，弱网中断时未合完的项标 `failed`，重试只处理这些；幂等键为 `类型:clientId@rev`——同一版本重复回传自动跳过、不重复入库，编辑产生新版本（`rev+1`）后可正常补合。
5. **旧数据升级回填**：本地存储带 `version`；v1 旧数据（记录无编号/无地点、轨迹点只有 `HH:mm`、样本无编号）升级到 v2 时，按现场时刻为记录编号（`GC-MMDD-序号`），缺地点的记录按**最近轨迹点**回填坐标，旧样本补 `YB-MMDD-序号` 编号，页面顶部展示回填结果。

## 页面操作
- 现场记录：观察 + 同批样本一次提交（样本自动关联观察）；记录 GPS/手工轨迹点。
- 同步区：断网/联网切换、按现场时刻同步、模拟“合 1 项后弱网中断”、整批再次回传（验重）。
- 待协调：保留 / 采用 / 合并三种决策；可再模拟更晚到件观察 stale 留痕。
- 观察记录：复核、改风险（低/中/高）、改地点、模拟另一人的晚到修改。
- 样本：提交核验 → 送检 / 核验通过；级联后可看到“待确认 / 退回待核验”。
